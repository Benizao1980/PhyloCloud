# PhyloCloud

**Phylogenetic diversity in context.** A reproducible, open-source command-line tool for drawing an unrooted reference phylogeny as a light diversity cloud, with a strong connecting subtree for selected genomes.

PhyloCloud is inspired by Ben Pascoe's hand-drawn GETcampy figure. It uses **one original tree and one coordinate system** for both layers: selected edges are an exact subset of the inferred full tree, not a second inferred or independently laid-out topology.

**Status: early, synthetic-only prototype (0.1.0a0).** The initial comparison with the original sketch identified important visual improvements before manuscript use. See [docs/SKETCH_REVIEW.md](docs/SKETCH_REVIEW.md).

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[test]'
pytest -q
phylocloud demo --outdir outputs/demo --seed 47 --references 900
```

That generates a deterministic synthetic Newick tree, metadata TSV, selected-genome list, style YAML and editable SVG/PDF plus 400-dpi PNG. The 900 references and nine selected genomes are fictional; **they are not GTDB or GETcampy biological data**.

Run the same pipeline on your own phylogeny:

```bash
phylocloud plot \
  --tree mytree.nwk \
  --metadata metadata.tsv \
  --selected focal_ids.txt \
  --config examples/config.yml \
  --out outputs/my_cloud
```

- Newick tips must have unique identifiers and finite, nonnegative branch lengths.
- Metadata is TSV/CSV with `genome_id` and `species`; optional `source`, `label`, and other columns.
- Selected list: one exact tip identifier per line; every selected genome must be present in the full tree.
- Figures export as SVG with editable text, vector PDF and high-resolution PNG.

## How it works

1. Read the original tree as an undirected weighted graph.
2. Choose an internal **display centre** that reduces imbalanced wedges. This is not biological rooting.
3. Allocate unrooted equal-arc angular sectors proportional to subtree terminal counts, placing every original edge at its inferred branch length.
4. Draw every original edge twice at low opacity (subtle broad halo plus fine core), optionally tinting pure-species branches using the Ben-style `getcampy.species` colours.
5. Peel away all unselected terminal branches to compute the unique minimum connected edge set spanning focal genomes; draw **only those original edges** in stronger warm-dark ink.
6. Add coloured genome markers and labels; labels may shift, but the tree coordinates never do.

The present equal-arc implementation is an initial layout. Future daylight optimisation must use topology-preserving subtree rotations without changing edge lengths. The visual interpretation of a phylogram should always be reported accurately.

## Population-structure fidelity

PhyloCloud treats the original tree as scientific evidence, not a decorative template. **Every genome, original branch, unrooted split, patristic distance and sampled reference count must be preserved.** The organic look should emerge from the actual phylogeny; we will not force species fans, move focal tips independently, or hide outliers to imitate a drawing. Background density represents the sampled reference collection, not necessarily prevalence. See the [scientific invariants and tests](docs/SCIENTIFIC_INVARIANTS.md).

## Scientific and graphical validation

- Tests cover original edge preservation and Euclidean lengths, selected-edge exactness, strict IDs and missing-length rejection, deterministic layouts and demo generation, pure/mixed taxonomy and SVG/PDF/PNG exports.
- One source Newick is always used for foreground and background.
- The synthetic demo passed seven local tests on 12 October 2026; GitHub Actions CI re-runs these tests on pull requests.
- **Not yet verified on the real 6,436 GTDB + 9 GETcampy MAG tree.** We will compare directly with the hand drawing before full-scale analysis.
- Do not infer a novel MAG-only phylogeny from the foreground subset, and do not infer ANI from nearest tree distances.
